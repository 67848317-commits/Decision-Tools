## 1. Executive Summary

Decision Tools is a high-performance, deterministic static web application built with Astro 7.3.3 and TypeScript. The site provides 10 financial and life trade-off decision calculators and 16 long-form analytical guides. Google Search Console has been submitted, GA4 is configured and actively receiving events, and Google AdSense is submitted for review with ads.txt properly deployed.

This audit evaluates the current architecture, production domain consistency, metadata, Schema.org structured data, analytics implementation, trust/legal pages, and content parity across all routes before any production modifications are implemented.

## 2. Current Architecture & Runtime

- **Framework:** Astro 7.3.3 (Static Site Generation / SSG mode).
- **Styling:** Tailwind CSS v4 (`@tailwindcss/vite` and `@import "tailwindcss";` in `src/styles/global.css` & `src/index.css`).
- **Scripts / Modules:** Deterministic client-side TypeScript calculations (`src/lib/decisions/*`), pure HTML/CSS SSR rendering with zero heavy runtime framework overhead on calculators.
- **Port & Host:** Port 3000, 0.0.0.0 (`astro dev --port=3000 --host=0.0.0.0`).
- **Dependencies:** Lean production stack with Astro, `@astrojs/sitemap`, `@tailwindcss/vite`, and TypeScript. No foreign runtime analytics libraries beyond Google gtag.js.

## 5. Structured Data (JSON-LD) Audit

- **Site-wide:**
  - `Organization` schema is rendered in `src/layouts/BaseLayout.astro` on every page.
  - `WebSite` schema is rendered in `src/layouts/BaseLayout.astro` on every page.
- **Guide Pages (`/guides/[slug]`):**
  - `Article` schema rendered with author, publisher, headline, description, URL.
  - `BreadcrumbList` rendered via `Breadcrumbs.astro`.
  - `FAQPage` schema rendered conditionally when `guide.faq && guide.faq.length > 0`.
- **Calculator Pages (`/decisions/[slug]`):**
  - `WebPage` schema rendered via `DecisionLayout.astro`.
  - `BreadcrumbList` rendered via `Breadcrumbs.astro`.
  - **Issue Identified:** While 5 calculators passed `faqs` and 5 passed `faqItems`, `DecisionLayout.astro` line 38 defaulted `faqItems = Astro.props.faqs || []`. Calculators passing `faqItems={faqList}` had their FAQs suppressed in the UI, and no `FAQPage` schema was emitted for calculators even when visible FAQs existed.
  - **Remedy:** Support `faqItems = Astro.props.faqItems || Astro.props.faqs || []` in `DecisionLayout.astro`, and conditionally attach `FAQPage` structured data to calculator pages when visible FAQs are present.
- **About Page (`/about`):**
  - `AboutPage` schema rendered with accurate description and URL.
  - `BreadcrumbList` rendered.

## 6. Article Schema Date Audit

- **Historical State:**  
  `src/pages/guides/[slug].astro` previously hardcoded static timestamps:
  ```typescript
  datePublished: '2026-09-01T08:00:00+00:00',
  dateModified: '2026-09-20T08:00:00+00:00',
  ```
- **Data Source Inspection (`src/data/guides.ts`):**  
  All 16 published guides specify month-level strings: `publishDate: 'September 2026'` and `modifiedDate: 'September 2026'`. No exact publication day or historical timestamps exist in the repository or project records.
- **Strict Anti-Fabrication Policy:**  
  - No exact dates (such as `2026-09-01` or `2026-09-20`) are fabricated or guessed.
  - Human-readable guide dates (`September 2026`) remain displayed to users in the UI.
  - The guide data model (`GuideItem`) includes explicit optional fields (`publishDateIso?: string`, `modifiedDateIso?: string`) for when exact dates are known.
  - For Article JSON-LD (`schema.org`), `datePublished` and `dateModified` are strictly output ONLY when supported by reliable, documented project data. Fabricated dates are not injected merely to satisfy Schema requirements.

## 8. Google Analytics 4 (GA4) Implementation & Privacy Compliance

- **Configuration:**  
  Configured in `src/layouts/BaseLayout.astro` via `PUBLIC_GA_MEASUREMENT_ID`.
  A safe non-blocking event dispatcher `window.trackDecisionEvent` protects UI thread execution if ad blockers or network errors intercept gtag.js.
- **Event Catalog:**
  1. `calculator_start`: Dispatched on first user focus/change in the input section.
     - Parameters: `{ calculator_slug: string, calculator_name: string }`
  2. `calculator_complete`: Dispatched with 800ms debounce upon successful input computation.
     - Parameters: `{ calculator_slug: string, calculator_name: string }`
  3. `calculator_reset`: Dispatched when user clicks a reset button.
     - Parameters: `{ calculator_slug: string, calculator_name: string }`
  4. `calculator_to_guide_click`: Dispatched when navigating from calculator to guide.
     - Parameters: `{ calculator_slug: string, calculator_name: string, guide_slug: string, guide_name: string }`
  5. `guide_to_calculator_click`: Dispatched when navigating from guide to calculator.
     - Parameters: `{ guide_slug: string, guide_name: string, calculator_slug: string, calculator_name: string }`
- **Data Protection Verification:**
  - **Zero financial parameters:** No salaries, mortgage amounts, debt balances, vehicle prices, or interest rates are sent to GA4.
  - **Zero PII:** No names, emails, IPs, or identifying metadata are gathered or sent.
  - **Strict adherence to Rule 18 & 19:** Parameters contain only static, non-sensitive taxonomy identifiers (`calculator_slug`, `calculator_name`, `guide_slug`, `guide_name`).

- **Issue Discovered in Footer (`src/components/Footer.astro`):**  
  Line 69 states:
  > `<span>Built with transparent formulas and zero tracking.</span>`
  This statement is factually inaccurate because Google Analytics 4 is integrated and active. Claiming "zero tracking" violates consumer trust and AdSense compliance.
- **Footer Navigation Gap:**  
  Footer currently links to `/about#privacy`, lacking dedicated links to `/privacy`, `/terms`, and `/contact`.
- **Required Update:**  
  1. Replace "zero tracking" statement with verified client-side privacy statement:  
     *"Calculator inputs are processed in your browser and are not stored on our servers."*
  2. Update footer navigation links to direct users to:

     - Terms of Service (`/terms`)
     - Contact (`/contact`)
